Work-stealing: how idle workers find work

Every cilk_spawn pushes a task onto the worker's own deque. A worker runs its deque from the bottom; when it runs dry it turns thief and steals the oldest task off the top of a random busy worker. No central queue, no planner — balance is what emerges.

# what each of the P workers runs while not done: while my_deque not empty: t = my_deque.pop_bottom() # my newest task — LIFO, cache-warm run(t) # running it may spawn & push more v = random(other workers) # pick a victim at random t = v.deque.steal_top() # take its oldest task — FIFO

The three rules

Owner → bottom

pop newest, LIFO

A worker always takes the task it spawned most recently. Its data is still in cache, and depth-first execution keeps memory use bounded — same order as the serial run.

Thief → top

steal oldest, FIFO

The top task is the earliest, highest-up spawn — typically the largest untouched subtree. Stealing it moves a big chunk of work in one shot, so steals stay rare.

Victim → random

no coordinator

An idle worker picks a victim at random. There is no shared queue to serialize on; random targeting spreads contention and is provably close to optimal.

Why this matters: work-stealing only does work when a worker goes idle, so it costs almost nothing until there is an imbalance to fix — then it fixes it automatically. That is a great deal on irregular workloads (qsort_steal.c) and a standing overhead with nothing to buy on regular ones (mergesort_balanced.c).
