Sorting networks

Bitonic Sort

A sorting algorithm with no branches and no data-dependent decisions. The sequence of comparisons is fixed before the data arrives — which is exactly what makes it run on SIMD hardware.

Most sorts decide what to do next by looking at the data. Bitonic sort does not. It runs a fixed network of compare-exchange operations, laid out in advance, and the same operations execute in the same order no matter what the input is. Sorting eight numbers always takes exactly 24 comparisons across 6 columns.

That rigidity costs comparisons — it does more work than an optimal sort. It buys something worth more on modern hardware: every column is independent, so a whole column runs in one SIMD instruction, and there is never a branch to mispredict.

1The comparator

The only operation. It takes two values and puts the smaller on one wire, the larger on the other. Which end receives the larger value is baked into the network — the arrow, not the data, decides.

2A bitonic sequence

A sequence is bitonic when it rises and then falls — or is a rotation of such a sequence. It has one peak, not many. This is the shape the whole algorithm is built to exploit.

3The half-cleaner

Here is the property everything rests on. Take a bitonic sequence of n values and compare each element with the one n/2 positions away. The result splits cleanly in two:

Every value in the left half is now smaller than every value in the right half — and each half is still bitonic. So the halves never need to be compared against each other again. Repeat on each half, and after log n rounds the sequence is sorted.

4The whole network

Step 3 needs a bitonic input, so the network builds one. It sorts adjacent pairs in alternating directions — up, down, up, down — which makes every neighbouring pair of runs bitonic. Merging those gives bitonic runs of 4, then of 8, doubling until the whole array is one sorted run.

What it costs, what it buys

The network for n values has log n stages, and stage i contributes i columns — so ½·log n·(log n+1) columns in total, each holding n/2 comparators.

Bitonic sort does more comparisons than a good quicksort. It wins anyway on the hardware it suits, for three reasons: the comparator is a min and a max with no branch to mispredict; every comparator in a column is independent, so a whole column becomes one SIMD instruction; and the pattern of comparisons is known at compile time, so the whole network can be unrolled flat with no loop and no indexing logic.

This is why it appears as the base case inside larger vectorised sorts — the small-array kernel that a bigger algorithm falls back on.
