CPU Cache Coherence

False Sharing

Four threads, each incrementing a counter no other thread ever touches — and yet they serialize. The CPU doesn't invalidate a variable; it invalidates a 64-byte cache line. If your counters are close enough to share one, every write evicts everyone else's copy.

The layout that causes it

Same four cores, same four counters — arranged two different ways in memory.

What that costs in wall-clock time

Two ways to fix it

From false_sharing.cpp — pad the layout, or stop writing to shared memory every iteration.

Structural — pad the line
struct alignas(64) Counter {
    long long value = 0;
    char _pad[56];
};
Counter counters[N];
// each counter now owns a full line
Forces the compiler to place every counter on its own cache line, so the hardware never has a reason to invalidate a neighbor.
Algorithmic — write once
long long local = 0;
for (int i = 0; i < N; i++)
    local++;          // register
shared[t] = local;    // one write
Zero cache traffic during the hot loop — the shared line is touched exactly once per thread, at the end.
Rule of thumb

If multiple threads write to different fields of the same struct, or to adjacent elements of the same array, check whether those fields fit inside a 64-byte span. If they do, you have false sharing — regardless of whether the threads share any actual data.
